# متطلبات قاعدة البيانات - منصة UnionSphere Enterprise

| المجال | النتيجة |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| الهوية العالمية      | إضافة عمود `global_id` من نوع UUID بفاصلة فريدة (UNIQUE) على جميع الجداول التشغيلية، مع مؤشر index للبحث السريع، والتأكد من الوجود في سجل التدقيق (audit_log) لكل عملية إنشائية وتحديثية |
| سلامة المفاتيح       | ضمان وجود Primary Key (PK) على جميع الجداول بدون استثناء: `organizational_entities`, `members`, `legal_entities`, `board_members`, `elections`, `activities`, `documents`, `violations`, `service_requests`, `licenses`, `profiles`؛ مع إضافتها عبر ALTER TABLE إن وجدت ناقصة |
| الفهارس والقيود      | صفر فهرس معطل (disabled index) وصفر قيود غير موثوقة (untrusted constraint)؛ مراجعة جميع الفهارس للتأكد من استخدامها، وإضافة فهارس ذكية على الحقول المستخدمة في البحث والتصفية (gov، status، dates)، وفرض جميع القيود بفكرة `NOT TRUSTED` وتُعاد تم التحقق منها |
| العزل                | فحص `tenant_id` على جميع الجداول التشغيلية الفعلية، بدون وجود سجلات بها `null` في القيود المفحوصة؛ إضافة عمود `tenant_id` UUID مع constraint `NOT NULL` وفهرس، وتفعيل Row Level Security (RLS) على جميع الجداول |
| المالية              | - إضافةForeign Key للعملة (currency_id referencing currencies table)<br>- منع المبالغ السالبة CHECK (amount >= 0)<br>- منع سعر الصرف غير الصحيح بفرضconstraintات على ratios<br>- منع العملة المفقودة مع مبلغ أجنبي بفرض FK مشروط وم Validation على وجود العملة عند وجود Amount أجنبي |
| القيود المرحلة       | القيود ذات الحالة `POSTED` أو `REVERSED` تصبح غير قابلة للتعديل أو الحذف;<br>- التحديث يكون بعكس (reversal) أو تسوية (correction entry)<br>- إضافة constraint check على حالة القيد تمنع التعديل إذا كان state IN ('POSTED','REVERSED')<br>- وظيفة لتوليد قيد تصحيح opposite entry |
| التوازن المحاسبي     | فحص القيود دون فروقات غير مقبولة;<br>- إضافة عرض (view) يتحقق من تعادل المدين والدائن;<br>- السماح بفروقات مسموحة (tolerance) محددة بقيمة صغيرة;<br>- التحقق من القيد المرحل الحالي (current posted entry) ضمن الفروقات المسموحة |
| التدقيق              | سجل تغيير تاريخي قبل/بعد مع المستخدم والجلسة والجهاز والموقع والهاش وسلسلة الأثر;<br>- إضافة الأعمدة: prev_hash, row_hash, sequence;<br>- تفعيل trigger للحفاظ على سلسلة الهاش;<br>- إضافة actor_id, ip_address, user_agent, session_id;<br>- وظيفة verify_audit_chain للتحقق من целостية السلسلة |
| البيانات الديناميكية | قيود JSON صحيحة للكيانات والسياسات والوركفلو والوسائط;<br>- التأكد من-type validation على полю field_type في table dynamic_fields;<br>- إضافة قيود check على JSON structure للسياسات والorkflows;<br>- تخزين الوسائط كـ JSON مع hash والتشفير |
| المزامنة             | Global Aggregate ID، إصدار الخادم، حالة التعارض، وآخر محاولة مزامنة;<br>- إضافة table sync_status أو حقل على الجداول الرئيسية:<br>  - global_aggregate_id UUID Unique<br>  - server_version INTEGER;<br>  - conflict_state TEXT DEFAULT 'none' CHECK (conflict_state IN ('none','version conflict','data conflict'));<br>  - last_sync_at TIMESTAMPTZ;<br>  - last_sync_status TEXT DEFAULT 'pending' CHECK (last_sync_status IN ('pending','success','failed')) |
| الترجمة              | GlobalId وUnique مركب حسب `key + culture` دون تكرار;<br>- إضافة table translations مع columns: key TEXT, culture TEXT, value_ar TEXT, value_en TEXT, global_id UUID,<br>- constraint Unique(key, culture) لضمان عدم التكرار;<br>- التأكد من وجود-index على كل من key و culture |
| الوسائط              | سجل رسمي للصور والوثائق والتوقيعات مع الهاش والتشفير والموقع والجهاز والاحتفاظ;<br>- إضافة table media_records مع columns:<br>  - id UUID PK;<br>  - file_hash CHAR(64) NOT NULL (SHA256);<br>  - encrypted_storage BOOLEAN DEFAULT true;<br>  - location_lat/lon NUMERIC;<br>  - device_id UUID;<br>  - captured_at TIMESTAMPTZ;<br>  - retention_policy TEXT;<br>  - associated_record UUID;<br>- تفعيل trigger لمسح السجلات المنتهية الصلاحية;<br>- Policy لتشفير البيانات الحساسة |
| السمات الحيوية       | سجل محكوم للقوالب الحيوية بالمراجع والهاش والموافقة والخوارزمية؛ دون تخزين خام غير محكوم;<br>- إضافة table biometric_templates مع columns:<br>  - id UUID PK;<br>  - template_hash CHAR(64) NOT NULL;<br>  - algorithm TEXT CHECK (algorithm IN ('Fingerprint','Face','Iris'));<br>  - reference_count INTEGER DEFAULT 0;<br>  - approval_status TEXT DEFAULT 'pending' CHECK (approval_status IN ('pending','approved','rejected'));<br>  - approved_by UUID;<br>  - approved_at TIMESTAMPTZ;<br>  - created_at TIMESTAMPTZ DEFAULT now;<br>- constraint منع تخزين template_raw;<br>- trigger للحذف automatic في حال انتهاك approval |
